# US Holding Site v2

## Что это

Корпоративный сайт группы компаний US Holding (`usholding.kz`) — 17 направлений,
портфолио проектов, аутентификация и личный кабинет сотрудников. Идёт миграция
с монолитного `index.html` (статика без бэкенда) на полноценную систему
с фронтендом, бэкендом и БД.

**Прод-версия сайта (текущий `index.html` в ветке `main`) живая и обслуживает
реальный трафик на `usholding.kz`. Не ломать, не трогать `main` напрямую.**
Вся разработка — в ветке `rebuild`, мердж только через Netlify Deploy Preview
после ручной проверки (см. Фазу 8 в ROADMAP.md).

## Технологический стек

- Frontend: Next.js 15 (App Router, React Server Components), TypeScript (strict), Tailwind CSS
- Backend: Next.js Route Handlers (`app/api/*/route.ts`) — отдельный сервис не нужен
- БД/Storage: Supabase (Postgres + Storage + автогенерируемая админ-панель данных)
- Аутентификация: Clerk — переход с CDN-скрипта на `@clerk/nextjs` SDK
- Формы: Web3Forms (без изменений) + дублирование заявок в Supabase `leads`
- Почта: Microsoft 365 / Outlook Web (без изменений, просто ссылка-переход)
- Хостинг: Netlify (Next.js Runtime, `@netlify/plugin-nextjs`)
- DNS: Cloudflare (`usholding.kz`, без изменений)
- Репозиторий: `github.com/KAZmake/usholding-site`
- Тесты: Vitest (unit), Playwright (e2e)
- Наблюдаемость: Sentry, Lighthouse CI

Подробности и рационale выбора — `docs/STACK.md`. Читать по необходимости,
не грузить в каждый промпт.

## Жёсткие правила

1. Никогда не пушить напрямую в `main` — только через PR из `rebuild` с прошедшим CI
2. Visual parity: дизайн, тексты и данные всех 17 компаний переносятся 1:1, без самовольных изменений копирайтинга
3. Секреты — только через переменные окружения (`.env.local`, Netlify env vars). Никогда не хардкодить ключи в коде (см. историю: текущий `index.html` уже содержит publishable-ключ Clerk и access-key Web3Forms в открытом виде — это нормально для **публичных** ключей, но `CLERK_SECRET_KEY` и `SUPABASE_SERVICE_ROLE_KEY` — только server-side, никогда в клиентский бандл)
4. Коммиты: Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:`)
5. Каждая задача — это PR с прошедшим lint + typecheck + тестами (см. Фазу 6 ROADMAP.md)
6. Не удалять и не переписывать `images/`, `logo/` в `main` до завершения Фазы 8 — текущий прод-сайт от них зависит
7. Сохранить три интеграции как есть, не искать им замену: Clerk (auth), Web3Forms (форма обратной связи), Microsoft 365 (корпоративная почта) — задача агентов улучшить *архитектуру вокруг них*, а не заменить их

## Агенты

- Оркестратор: планирует, делегирует через Task tool, следит за прогрессом
- Глобальные (`~/.claude/agents/`): `backend-dev`, `frontend-dev`, `qa-agent`, `researcher`
- Проектные (`.claude/agents/`):
  - `migration-agent` — перенос монолитного `index.html` (контент, дизайн, 17 компаний) в Next.js без визуальной регрессии
  - `supabase-agent` — схема БД, миграции, RLS, Storage, типы
  - `seo-perf-agent` — Core Web Vitals, изображения, SEO-теги, Lighthouse CI
  - `devops-agent` — Netlify Next.js Runtime, переменные окружения, CI/CD, Sentry, дашборд

## Рабочий процесс оркестратора

1. Читай `ROADMAP.md` → найди первую задачу с `- [ ]` (фазы идут по порядку, Фаза N+1 не начинается, пока в Фазе N не закрыты блокирующие задачи — см. зависимости в `docs/STACK.md`)
2. Читай `BOARD.md` → проверь, что задача не занята, и проверь секцию `Human Input` — нет ли ответа на ранее заданный блокер
3. Запиши план в `BOARD.md`
4. Делегируй субагентам через Task tool (выбери подходящего: проектного или глобального)
5. Дождись результата → обнови `BOARD.md` и `ROADMAP.md` (`- [ ]` → `- [x]`)
6. Обнови дашборд (см. ниже) → обязательно!
7. Переходи к следующей задаче

## Связь с человеком (Telegram)

Если для задачи нужно действие, которое может сделать только человек —
регистрация в стороннем сервисе, получение API-ключа, оплата, подтверждение
почты и т.п. — не блокируйся молча. Опиши это в `BOARD.md` → `## Blockers`
максимально конкретно: что нужно сделать и что именно вернуть (например:
"Зарегистрируй проект на supabase.com, верни SUPABASE_URL и ANON_KEY").

Отдельный сервис на сервере (`telegram_relay.py`) следит за этой секцией и
пересылает блокер в Telegram, в отдельный топик этого проекта. Ответ
человека автоматически появится в `BOARD.md` → `## Human Input`. Перед
началом каждой новой задачи (шаг 2 выше) проверяй эту секцию — если ответ
есть, используй его, реализуй и убери закрытый пункт из `Blockers`.

## Дашборд GitHub Pages

Дашборд живёт в `/docs`, а не в корне репозитория — корень (`index.html`)
обслуживает реальный прод-трафик через Netlify, и его нельзя занимать под
служебную страницу прогресса.

GitHub Pages: Settings → Pages → Source: Deploy from a branch → Branch: `rebuild`,
folder: `/docs`. Это сделано намеренно: вся разработка идёт в `rebuild` (правило 1),
и если привязать Pages к `main`, дашборд будет показывать 0% до самого релиза
в Фазе 8. После финального мерджа в Фазе 8 можно переключить источник на `main`.

URL: `https://kazmake.github.io/usholding-site/`

> Репозиторий публичный (с 2026-06-21) — это требование GitHub Pages на
> бесплатном плане. История проверена на секреты перед сменой видимости —
> найдены только публичные ключи Clerk (`pk_live_`/`pk_test_`), они и
> предназначены для клиента. Реальных секретов в коде/истории нет (см.
> правило 3) — это не повод их туда добавлять.

### ОБЯЗАТЕЛЬНО после каждой выполненной задачи:

**A. Обнови `docs/index.html`:**
1. Найди задачу по тексту
2. `class="task "` → `class="task task-done"`
3. `task-icon todo">○` → `task-icon done">✓`
4. Пересчитай `phase-footer`: «X из Y задач выполнено»
5. Обнови `phase-progress-fill` width: (выполнено/всего × 100)%
6. Бейдж фазы: хоть одна выполнена → `badge-active">В процессе` + процент; все выполнены → `badge-done">Завершено` + 100%
7. Обнови общий прогресс: `overall-label` («Общий прогресс — N из M задач выполнено»), `overall-fill` width, `overall-pct`, `overall-sub` («N / M»)
8. Обнови дату в `.updated`

**B. Закоммить и запушить:**
```bash
git add docs/index.html ROADMAP.md BOARD.md
git commit -m "progress: [название задачи] ✓"
git push origin rebuild
```
Дашборд обновится через ~2 минуты (Pages деплоится из `rebuild`, см. выше).
